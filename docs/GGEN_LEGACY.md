# How `ggen-create` powers `ggen-legacy`

## Category boundary

```text
working predecessor
  └─ ggen-create legacy.plan        SELECT/CONSTRUCT only
       └─ admitted manifest + ontology + receiving contract
            └─ ggen-create legacy.power   confirmed Broker DO
                 └─ receipted receiving bundle
                      └─ ggen projects templates from admitted authority
                           └─ ggen-legacy independently verifies behavior and replay
```

`ggen-create` does not replace `ggen` and does not certify `ggen-legacy`. It reverse-compiles an exact, bounded predecessor tree into the authority inputs that the manufacturing and receiver rails need.

## Workstream handoff

| Workstream | Owner after `legacy.power` | Standing manufactured by `ggen-create` |
|---|---|---|
| A — observe | `ggen-create` | `ALIVE` for the bounded file/digest manifest |
| B — align | shared | `PARTIAL_ALIVE`; filenames classify evidence but do not prove intent |
| C — contract | `ggen-create` | `ALIVE` for the receiving-contract projection |
| D — model | `ggen-create` | `ALIVE` for deterministic JSON and RDF projections |
| E — templates | `ggen`/`ggen-legacy` | `UNKNOWN` |
| F — manufacture | `ggen` | `UNKNOWN` |
| G — independent verification | `ggen-legacy` | `UNKNOWN` |
| H — replay | `ggen-legacy` | `UNKNOWN` |
| I — release | release authority | `UNKNOWN` |
| J — sunset | customer authority | `UNKNOWN` |
| K — portfolio standing | `ggen-legacy` | `UNKNOWN` |

## CLI through the canonical Broker

Planning is non-actuating:

```bash
GGEN_CREATE_SOURCE_COMMIT=<exact-40-character-commit> \
  ggen-create --json skills execute legacy.plan --arguments '{
  "subject_root": ".",
  "output_root": "foundry/generated/ggen-create",
  "program_id": "retail-order-modernization"
}'
```

Manufacture requires explicit confirmation and emits both a bundle receipt and the native Broker receipt:

```bash
GGEN_CREATE_SOURCE_COMMIT=<exact-40-character-commit> \
  ggen-create --json skills execute legacy.power --confirm --arguments '{
  "subject_root": ".",
  "output_root": "foundry/generated/ggen-create",
  "program_id": "retail-order-modernization"
}'
```

Independent intake verification is non-actuating:

```bash
ggen-create --json skills execute legacy.verify --arguments '{
  "bundle_root": "foundry/generated/ggen-create",
  "subject_root": "."
}'
```

## Generated receiving bundle

The bundle contains:

- `manifest.json`: exact observed file set, modes, sizes, classes, and SHA-256 digests;
- `ontology.ttl`: deterministic RDF projection of the observed subject;
- `receiving-contract.json`: explicit producer/receiver ownership and refusal conditions;
- `ggen.toml`: the manufacturing entry point;
- `receipt.json`: digest and mode binding for every generated byte, the admitted subject, and producer identity;
- `verify_bundle.py`: standalone output-integrity, exact source-set, mode, provenance, and subject-replay verifier;
- `replay_bundle.py`: standalone predecessor-drift detector;
- `templates/.keep`: an intentionally empty template boundary for receiver-owned workstream E.

## Claim ceiling

A valid bundle proves only that a bounded predecessor observation was deterministically converted into a coherent, replayable receiving input. It does **not** prove real `ggen sync`, behavioral equivalence, production readiness, certification, release, or predecessor retirement.
